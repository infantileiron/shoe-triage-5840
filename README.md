# 照台舞服 · 练功鞋返修分诊

把练功鞋的历史维修工票、分诊规则和主管签发单放在同一个工作台。分析员用过去的实际处置训练分类树，主管用较新的工票复核规则并决定每一双鞋的最终工序。

## 业务现场

照台舞服是一支模拟的六人小团队，为青禾舞社、临河少年宫、照台排练组和岚桥艺校收修排练鞋。接件员记录鞋型和损伤，维修师傅按补胶、换底、报废三个工序回填结论。以前，照片在群里，测量和签发在同一张共享表上。相近磨损的鞋可能由两位师傅给出不同去向。用全部旧工票试规则会掩盖新鞋批次的偏差。一条派工记录也很难追溯到当时的规则和主管的现场判断。

接件测量和完修回签进入历史退修登记簿。分析员冻结测量证据、做时间留出评估，主管把审核通过的树发到工位。新鞋生成可解释的建议，主管检查实物后签发。排班人员下载已签发 CSV 用于当班派工。

| 席位 | 主要页面 | 权限与典型动作 | 演示工号 | 演示密码 |
| --- | --- | --- | --- | --- |
| 维修主管 | 留出评估、个案分派、值班日志 | 查看草案和失败原因，记录复核理由，发布一份生效规则，核对实物并签发或改派 | `owner` | `ShoeOwner5205!` |
| 分诊分析员 | 历史退修、训练方案、留出评估、个案分派 | 登记或校订完修工票，保存新版本，入队计算，导出留出明细并用生效规则出建议 | `analyst` | `ShoeAnalyst5205!` |
| 调度观察员 | 历史退修、训练方案、留出评估、个案分派 | 查阅历史工票、已发布规则及其报表、已签发的分诊单，下载派工 CSV | `viewer` | `ShoeViewer5205!` |

## 模拟工作日

1. 08:45，周芮核对 `WX-0001` 至 `WX-0048`。`WX-0043` 的磨损率为 46%，开胶 19 mm、鞋底变薄，实际工序是补胶。
2. 09:00，收齐青禾舞社的 `WX-0049` 帆布半底鞋完修签回，收件日填 `2026-11-21`，录入 20% 磨损、16 mm 开胶、鞋底完整、实际补胶。
3. 09:15，保存「十一月返修 · 复核版」，选择 `2026-11-10` 为留出起始日，α 填 `0.026`，最小叶样本填 `2`，深度上限填 `5`，勾选三个测量特征。
4. 09:20，点击「冻结样本并运行」。后台用 36 张训练工票分裂和剪枝，用其余 13 张工票计算混淆矩阵。剪枝路径从 7 叶到 6 叶，留出判中 12 张，`WX-0043` 被多派到换底。
5. 09:30，下载 `holdout-2.csv`（空库演练中的运行号）。沿 `WX-0043` 的磨损阈值核对误判路径。随后把 `WX-0049` 的开胶长度校订为 17 mm，该运行的指纹和 CSV 仍可追溯到 16 mm 的冻结工票。
6. 09:40，唐屿以维修主管身份记录一张补胶被多派换底，并发布这次评估。新分诊单采用该运行号。
7. 10:10，周芮登记 `FZ-0001`，青禾舞社帆布半底鞋，磨损 51%、开胶 27 mm、鞋底变薄。命中 `51% ≤ 65.5%`、`51% > 44%`，建议换底。主管试弯后确认仅外侧开胶，改派补胶并签发。
8. 10:25，许桥下载 `triage-dispatch.csv`，用「最终处置」列把 `FZ-0001` 派给补胶工位。表中保留模型建议、规则运行号和主管签发说明。

首次启动会生成三个席位、48 张模拟工票和一份待复核的基准运行，日期从 2026 年 10 月 5 日到 11 月 21 日。基准方案使用相同截止日和参数，留出 12 张，判中 11 张。seed 按工号、工票编号和参数版本名保留已有行，重复执行只补缺失自然键。基准运行随首个基准版本一起写入。

## 计算与审阅口径

- 训练日期严格早于起始日，留出日期大于等于起始日。预测输入为磨损率、开胶长度和鞋底状态中的勾选项，目标为实际处置。收件日仅用于切分。
- CART 在每个非叶节点用训练数据最大化 Gini 降幅。`G(t) = 1 − Σₖ pₖ²`，子节点按样本数加权。数值特征枚举相邻不同观测的中点，鞋底状态枚举「一个状态 / 其余状态」的二分。受最小叶样本、深度和严格正增益约束。平局按磨损、开胶、鞋底状态的顺序，再按阈值或状态顺序处理。叶类按多数票，票数相同时优先报废，其次换底。
- 最弱环节剪枝用 `R(T) = Σₗ [nₗ / N × G(l)]` 计算子树训练风险。每步剪掉达到最小 `g(t) = [R(t) − R(Tₜ)] / (|leaves(Tₜ)| − 1)` 的分支，并记录临界 α 和叶数。取临界 α 不超过方案 α 的最小子树。分裂和剪枝比较使用精确分数，留出数据只参与评估。
- 混淆矩阵以实际处置为行、预测处置为列。准确率是对角线之和除以留出数。宏平均召回是三类召回率的算术平均。任一集合缺类或训练样本无法满足最小叶样本要求时，任务以原因结束，报告无法发布和导出。
- 每次运行固定参数版本和排队瞬间的全部工票，按收件日期、工票号排序后对规范 JSON 取 SHA-256。运行报告包含剪枝路径、规则树、逐票预测及决策路径。分诊单固定创建时的生效运行和叶样本构成。发布后，之前的版本进入归档，可继续查阅。
- PostgreSQL 队列用行锁认领工作，三分钟租约失效后可重领，旧租约无法覆盖新执行结果。发布与个案分派共享事务锁，保证新分诊单绑定当时唯一生效的版本。签发和审计在同一事务写入。

## 启动与开发

需要 Docker 和 Compose。源码目录中运行：

```bash
cp .env.example .env
docker compose up --build --wait
# 如需显式补种数据
docker compose exec -T backend python -m scripts.seed_demo
```

| 入口 | 默认地址 |
| --- | --- |
| 工作台 | `http://127.0.0.1:18274` |
| FastAPI 文档 | `http://127.0.0.1:19274/docs` |
| PostgreSQL 16 | `127.0.0.1:17774`，数据库 `triage` |

| 服务 | 技术与职责 |
| --- | --- |
| `frontend` | Nginx，静态 HTML、CSS 和原生 JavaScript。`/api/` 转发到后端，页面使用散列路由 |
| `backend` | Python 3.11、FastAPI、psycopg、PyJWT。启动时执行 SQL 初始化和可选 seed |
| `worker` | Python 3.11，读取数据库队列，执行 CART、剪枝和时间外评估 |
| `db` | PostgreSQL 16，记录业务实体、冻结数据和审计 |
| `redis` | Redis 7，维护登录限流窗口 |

开发时可直接编辑 `frontend/src` 中的模块并重建前端服务。后端本地开发需要 Python 3.11 以及可达的 PostgreSQL 16 和 Redis。安装 `backend/requirements.txt`，设置 `DATABASE_URL`、`REDIS_URL`、`JWT_SECRET` 后，在 `backend` 下运行 `python -m uvicorn src.main:app --reload --port 8000`。计算单独由 `python -m src.worker` 运行，需要可写的 `/artifacts` 心跳目录。批次验收使用共享的 `scripts/verify-project.sh gb-5205`，会创建并清理测试栈及其数据卷。手动开发栈可用 `docker compose down` 停止并保留数据卷。

| 环境变量 | 用途 |
| --- | --- |
| `COMPOSE_PROJECT_NAME` | 默认 `shoe-triage`，用于隔离 Compose 项目和容器 |
| `FRONTEND_PORT` / `BACKEND_PORT` / `DB_PORT` | 三个回环监听端口，默认 `18274` / `19274` / `17774` |
| `NETWORK_SUBNET` | Compose 默认网络，默认 `10.221.205.0/24` |
| `POSTGRES_PASSWORD`、`JWT_SECRET` | 数据库密码与签名密钥，示例值面向本地演示。数据库密码应为可放入连接 URI 的值 |
| `SEED_DEMO` | `true` 时启动过程补种模拟工号、工票和基准方案 |
| `DATABASE_URL`、`REDIS_URL` | Compose 注入服务内连接地址，直接启动 Python 时须设置 |

`backend/migrations` 定义持久层，`backend/src` 分开维护认证、请求校验、记录与计算服务，`backend/scripts` 持有可复用的模拟数据。`frontend/src` 分为 API、会话与业务状态、页面、共用组件、样式和字体。验收脚本、截图及证据位于批次 `test-artifacts/gb-5205`。

共享枚举见后端 `src/constants/domain.py` 和前端 `src/constants/domain.js`。席位用于账号、认证路由和导航；工序和鞋底状态用于样本、分诊单校验，计算规则、表格与导出；特征用于版本校验、规则路径和方案表单；运行状态和发布状态用于 SQL 约束、队列、发布可见性及评估页标签。

## 使用范围

种子数据为模拟工票，12–13 张留出样本的得分只适用于该演练。测量记录为整百分比和毫米，模型未纳入鞋面破损、材质差异或鞋码。真实派工以主管签发为准。本地单车间演示提供单条工票录入与校订，共享账号为预设种子，暂无账号管理和工票批量导入界面。重复启用种子只保留原有修改，首次建库后关闭种子也会保留已有演示账号。
